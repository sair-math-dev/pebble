# 设计依据与需求映射

依据：用户提供的《Open Models for Scientific Research — A SAIR initiative for the scientific community》。以下是需求摘要，不是原文全文。产品设计中的新增选择是提案，不代表已实现能力。

产品边界修订：写作协作归 Clay，Pebble 应提前准备接入所需的项目、权限、版本、提交与引用接口，但不提供写作协作功能。Pebble 不引入编辑器、CRDT、共同编辑或文稿实时同步服务。论文提交、阅读与引用保留；完整 Git 仓库与 Cargo 式包管理共同构成成果版本、验证和发布基础，复杂项目协作按具体任务推进。

2026-09-09 用户架构修订：研究源码必须以 Git 为版本事实源，clone、fetch、push、提交历史、分支和标签属于核心能力。发布和依赖固定 `repo_id`、精确 commit 及必要的包路径；包快照只是该 commit 的导出交付对象。同一仓库按同一 commit 整体检查，不按各定理最后修改的 commit 混装；修改生成新 commit，旧发布与引用不可覆写。当前源码、数据库 schema 和部署配置尚未实现这一 Git 基础，已有验收属于迁移前快照闭环；本轮是架构修订，不是 Git 实现交付。

结构参考：按用户建议参考 Hugging Face Hub 的领域目录、卡片、文件版本、使用入口和 Collections。映射为科研成果、包与精确结果，不自动扩展到应用托管或写作功能。

2026-09-09 用户补充：Pebble 面向公网，交付需包含部署与运维细节；首阶段按 **10,000 注册用户**设计，长期目标为 Hugging Face 级平台规模。注册用户不等于日活或同时在线。具体容量假设、资源起点、实测边界与分阶段扩展见 [容量目标](capacity.md)，部署配置与恢复流程见 [部署说明](deployment.md)。长期规模目标不要求首个闭环预建全部未来服务。

用户进一步决定：先采用运维签发的单次、限时、可撤销邀请，不开放自主注册或无限转邀；随后建立类似 Google Scholar 的可追溯学术声誉档案。科学引用、形式化贡献、实际直接使用与独立复用、维护贡献分别呈现，保留全量/去自引视图和平台覆盖说明。声誉不替代 Slate 检查、审核或资源预算；新人有基础额度，扩额初期人工批准。长期归档先按有限配额接纳，发布后不因删仓重建返还占用。邀请流程已实现，见 [增量验收](implementation-status.md#邀请制增量验收)；声誉与累计成本预算仍为设计要求。当前作者及 citations 是作者填写的字符串，尚无已核实的人物、成果及引用映射，不能计算可信 h-index 或声称已有学术身份认证。

| 原始目标或约束 | Pebble 中的落实 |
| --- | --- |
| 科研成果成为开放前沿模型的能力来源 | 提供可复用研究成果和具有来源、权限、验证状态的贡献导出；训练与模型服务独立推进 |
| Pebble 扮演科学领域 GitHub，并成为研究发布和引用的入口 | 研究项目托管、版本管理、协作、成果阅读、发现和引用是一体化产品 |
| 从单个引理到完整论文均可发布 | 项目可发布一个或多个包；结果拥有版本绑定的独立定位与引用 |
| 包含贡献的全部形式化代码和数据 | 发布绑定 Git commit、包路径、完整源码、数据清单、精确依赖及工具链；固定源码、环境和证据仍由 Slate 核查 |
| 包管理负责安装、依赖、版本；工具链检查接口使用 | Pebble 提供注册与分发协议，Slate 客户端处理本地依赖，Slate 检查器决定验证结果 |
| 所有形式化代码验证通过方可发布 | 正式发布必须通过验证和基本提交审核；开发草稿与正式发布显著区分 |
| 提交审核不评判科学重要性 | 审核问题、结果、假设、引用和使用说明等要求；社区评价另行展示 |
| 理论物理证明基于明示物理假设 | 分开展示数学推导验证、物理假设、数据及其适用性；不把验证徽章解释为实证成立 |
| 人主要阅读自己的新贡献，并可追查证明基础 | 论文、结果、证明与依赖相互链接，支持逐层展开 |
| Clay 整合写作、开发、学习与 AI | 写作协作由 Clay 实现；Pebble 现在设计稳定项目/结果身份、权限和成果提交接口，接收 Clay 产出 |
| 预计约 90% 使用场景涉及 AI 辅助写作 | 指导 Clay 的使用体验；Pebble API 支持授权客户端和 agent 提交成果，不提供写作编辑器 |
| 研究记录保留任务、假设、工具调用、失败与修复 | 研究记录与已验证包独立建模；失败不得作为已验证成果发布 |
| Clay 记录默认贡献训练，可退出；退出失去免费额度资格 | 单独建模训练选择与免费额度资格，并保留 BYOK 路径 |
| 私有项目同样遵循默认训练规则，需显著、反复提醒 | 访问权限与训练选择分别展示；提醒未发表研究的保密影响 |
| 公开附加对话可选，且独立于训练贡献 | 三个独立维度：项目访问、记录公开、训练授权；导出检查来源与权利 |
| 社区竞赛贡献证明、反例、批评、修复、方法与部分进展 | 挑战与贡献记录关联到项目或结果，支持署名、引用及验证状态 |
| 保护评估题目及其变体，避免训练污染 | 保留问题族、项目与用途标记；评估隔离在导出和训练管线强制执行 |
| 最强自用模型公开权重，并提供 API 和科研/学习额度 | 模型发布与服务属于 SAIR 其他系统；Pebble 提供成果与合资格数据接口 |

尚未由原文确定：仓库拆分、项目与包的数量关系、页面结构、论文提交格式、引用标识实现、服务技术栈。首版设计明确提出这些选择，后续可单独决策。
