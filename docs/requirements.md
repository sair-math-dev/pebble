# 设计依据与需求映射

依据：用户提供的《Open Models for Scientific Research — A SAIR initiative for the scientific community》。以下是需求摘要，不是原文全文。产品设计中的新增选择是提案，不代表已实现能力。

当前范围修订：用户明确将写作协作排除在本期之外。原文中的 Clay/AI 写作目标作为长期背景保留；不为本期引入编辑器、CRDT、共同编辑或文稿同步服务。论文提交、阅读与引用保留；当前优先 Cargo 式包管理和 GitHub 风格浏览，完整 Git 托管及复杂项目协作后置。

| 原始目标或约束 | Pebble 中的落实 |
| --- | --- |
| 科研成果成为开放前沿模型的能力来源 | 提供可复用研究成果和具有来源、权限、验证状态的贡献导出；训练与模型服务独立推进 |
| Pebble 扮演科学领域 GitHub，并成为研究发布和引用的入口 | 研究项目托管、版本管理、协作、成果阅读、发现和引用是一体化产品 |
| 从单个引理到完整论文均可发布 | 项目可发布一个或多个包；结果拥有版本绑定的独立定位与引用 |
| 包含贡献的全部形式化代码和数据 | 发布绑定源码、数据清单、依赖及工具链；大文件采用固定摘要的托管对象 |
| 包管理负责安装、依赖、版本；工具链检查接口使用 | Pebble 提供注册与分发协议，Slate 客户端处理本地依赖，Slate 检查器决定验证结果 |
| 所有形式化代码验证通过方可发布 | 正式发布必须通过验证和基本提交审核；开发草稿与正式发布显著区分 |
| 提交审核不评判科学重要性 | 审核问题、结果、假设、引用和使用说明等要求；社区评价另行展示 |
| 理论物理证明基于明示物理假设 | 分开展示数学推导验证、物理假设、数据及其适用性；不把验证徽章解释为实证成立 |
| 人主要阅读自己的新贡献，并可追查证明基础 | 论文、结果、证明与依赖相互链接，支持逐层展开 |
| Clay 整合写作、开发、学习与 AI | 属于 Clay/长期愿景；本期 Pebble 接收外部产出的论文和项目，不实现写作工作流 |
| 预计约 90% 使用场景涉及 AI 辅助写作 | 保留为长期使用预期，不作为本期编辑器或写作协作需求 |
| 研究记录保留任务、假设、工具调用、失败与修复 | 研究记录与已验证包独立建模；失败不得作为已验证成果发布 |
| Clay 记录默认贡献训练，可退出；退出失去免费额度资格 | 单独建模训练选择与免费额度资格，并保留 BYOK 路径 |
| 私有项目同样遵循默认训练规则，需显著、反复提醒 | 访问权限与训练选择分别展示；提醒未发表研究的保密影响 |
| 公开附加对话可选，且独立于训练贡献 | 三个独立维度：项目访问、记录公开、训练授权；导出检查来源与权利 |
| 社区竞赛贡献证明、反例、批评、修复、方法与部分进展 | 挑战与贡献记录关联到项目或结果，支持署名、引用及验证状态 |
| 保护评估题目及其变体，避免训练污染 | 保留问题族、项目与用途标记；评估隔离在导出和训练管线强制执行 |
| 最强自用模型公开权重，并提供 API 和科研/学习额度 | 模型发布与服务属于 SAIR 其他系统；Pebble 提供成果与合资格数据接口 |

尚未由原文确定：仓库拆分、项目与包的数量关系、页面结构、论文提交格式、引用标识实现、服务技术栈。首版设计明确提出这些选择，后续可单独决策。
