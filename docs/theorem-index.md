# Theorem indexing：从已检查声明到可用候选

记录：TECH-0003；状态：proposed；日期：2026-09-08。

目标：每个正式发布的可引用定理自动成为结构化目录中的一条记录，研究者按名字、描述、公式或当前证明目标找到它，并能取得准确的版本、前提、引用和导入方式。本方案不实现自动写作；Clay 使用检索 API，Slate 负责最终形式检查。

## 1. 两项不同的任务

| 任务 | 输入 | 输出 |
| --- | --- | --- |
| 定理目录提取 | 固定包、已检查声明和完整覆盖报告 | 精确声明记录、出处、目标、假设、证据和依赖 |
| 检索索引构建 | 声明记录及有来源的解释 | 名称/词项、公式结构、语义向量和图邻接索引 |

目录内容来自 Slate 检查路径，不通过正则扫描 `theorem` 或让 LLM 从论文猜出正式声明。PDF 中没有形式化绑定的定理可以作为论文文本被搜索，但不能混入正式已检查定理目录。

检索记录是可重建的数据库投影，不是新的证明 IR。改变分词器、embedding 或排序算法不改变定理、证据和包的身份。

## 2. Slate 现有基础与缺口

核查固定提交 `bab9a76e7864c33e4a90ec6f1b41ba972920d4bf`：

- `ResolvedTermNode` 包含 Bound、Const、App、DefApp，公式包含 Eq、Rel、And、Or、Imp、Forall、Exists 等；绑定上下文及定义身份是显式的。
- `TermId`/`FormulaId` 是带 arena 身份的内部句柄，不能原样存入跨进程索引。导出必须使用稳定的外部引用或自含结构投影，并绑定精确环境。
- `print_published_source` 已输出 FactId、canonical target、theory/target/certificate hash、依赖和假设闭包等，但当前打印是单结果视图，尚无完整包级定理索引接口。
- 所需新增工作是由 Slate 导出已检查声明的结构化目录，并把索引字段关联到相同检查结果；Pebble 不重新实现公式解析器或自行解码内部缓存来生成可信目录。

源码：[公式表示](https://github.com/sair-math-dev/loom-lang/blob/bab9a76e7864c33e4a90ec6f1b41ba972920d4bf/tools/slatec/src/fol/resolved_formula.rs)、[结果输出](https://github.com/sair-math-dev/loom-lang/blob/bab9a76e7864c33e4a90ec6f1b41ba972920d4bf/tools/slatec/src/main.rs)。本轮核查是静态阅读，未实现导出器或运行搜索系统。

## 3. 一条定理记录保存什么

复用现有 `result_revisions`，按声明种类区分 theorem、definition、axiom 等，避免建立另一套相互漂移的 theorem/result 真相。索引单元是**一个精确版本中的可导出声明**；不将证明中每个局部 have 自动做成全球可导入定理。

| 字段组 | 内容与来源 |
| --- | --- |
| 身份 | result revision ID、package snapshot digest、ModuleId、module interface hash、FactId；与完整检查记录关联 |
| 命题 | 原始声明、可阅读的精确陈述、绑定变量/排序上下文、解析后的完整公式引用、target hash |
| 环境 | logic、ambient theory、definition environment 的精确身份 |
| 条件 | 显式参数和前提、逻辑/理论公理与经典原则等实际假设闭包；两者分别展示 |
| 符号 | 命题中用到的已解析函数/关系/定义身份，以及出现于前提或结论的位置角色 |
| 证据 | 检查记录、certificate/provenance 引用、直接证明依赖及完整闭包引用 |
| 学术信息 | 标题、作者、原论文、形式化贡献者、领域、来源说明和例子 |
| 自然语言说明 | 作者注释/论文中绑定段落；可选机器生成解释，记录来源、模型与审核状态 |
| 出处与使用 | 固定版本文件路径/源范围、引用落点、包安装与 import 信息 |

`FactId` 或 theorem name 单独不足以当全站唯一键。相同命题的两个证明、同名不同版本、不同理论里的同名符号均保留各自身份。可给相近版本做展示分组，但不得因此合并作者、假设或证据。

完整公式保留原作用域与连接词。只对可识别的外层参数和 implication spine 提取用于检索的前提/结论视图；不能把任意嵌套的析取、存在量词或蕴含都摊平成无作用域的条件列表。陈述中的前提与证明实际使用的基础公理是不同维度，例如“n > 0”和“依赖经典选择原则”不能混在同一个标签里。

## 4. 构建四类索引

### A. 名称和文本

索引全名、短名、别名、标题、注释、自然语言说明及相关学术术语。名称同时保留精确值和搜索分词，例如 `LeftInverseUnique` 可拆成 left/inverse/unique；中文分词和中英文对照独立评测，不能假设英文全文词典覆盖中文。

精确查找和前缀用 B-tree/专用前缀索引，正文先用 PostgreSQL 全文 GIN。这提供能解释、能测量的基础检索，不要求先训练模型。

### B. 公式结构

从 Slate 的已解析公式导出：顶层逻辑形式、结论头符号、排序、前提头符号、常数/定义集合及有界子项特征。索引保留精确符号及环境身份，另可保留弱化的形状特征用于扩大召回。

绑定变量按结构位置处理以消除无关名字差异；保留排序、量词顺序和同一变量重复出现的关系。不能把 `f(x,x)` 与 `f(x,y)` 当成相同模式，不能仅用文本 `*` 识别运算。检索用 fingerprint 不是 Slate 的 target hash，不成为命题等价证明。

初版采用 `(theory, conclusion_head, sorts)` 和符号倒排列表；规模需要时再试 discrimination tree 或 term-pattern 索引。可以为等式两侧提取检索视图，但最终换向、实例化或重写由普通 Slate 规则完成。定义展开只用受控的检索视图；不能为索引把所有不透明定义展开，或假设交换律/结合律普遍成立。

索引完整声明与前提/结论两个角色，避免只检索结论后漏掉关键条件。结构匹配失败也不证明某定理无用：它可能是需要中间变换的前提，所以结构匹配是独立召回通道，不是所有自然语言搜索的硬性排除条件。

### C. 语义向量

为每个定理构造有界语义描述：名称、准确陈述、显式条件、相关定义的短说明、作者注释。自然语言表达和形式化表达可以分别编码，再按同一 result revision ID 汇总。不能只把整篇论文切成随机段落后失去 theorem 边界，也不把完整证明体当作默认检索文本。

自动生成解释可以提高术语覆盖，但可能写错条件。保留机器来源且作为辅助索引；原声明随结果返回，生成解释不覆盖它。定义背景按预算选择，不能把整个传递依赖库拼进每条向量。

LeanSearch v2 的标准模式使用带上下文的非形式化语料及 embedding/reranker，提供了可借鉴的检索路径；其跨多步证明的全局 premise retrieval 是更大的任务，不作为 Pebble 搜索首发承诺。[LeanSearch v2 论文](https://arxiv.org/abs/2605.13137)。

向量层可以用 PostgreSQL + pgvector，先测精确近邻，确有需要再引入 HNSW。ANN 是召回率与速度的权衡；权限/版本筛选会影响候选数量，需要过滤分区、适当增加扫描或精确检索，并验证查询计划，不能以最终条数不足推断没有相关定理。[pgvector 索引与过滤](https://github.com/pgvector/pgvector#filtering)。

### D. 关系索引

分开保存 `mentions_symbol`（命题提及符号）、`uses_fact`（证明实际直接使用）、`cites_work`（学术引用）。反向索引支持“有哪些结果使用这个引理”“有哪些定理涉及这个定义”。它们不是同一种引用计数。

索引构建遍历去重后的公式 DAG 和直接边；不展开所有依赖路径。子项出现的作用域/角色要保留，预算截断时记录哪些检索特征不完整，不把截断后的列表宣称为完整数学依赖闭包。

## 5. 检索流程与两种使用场景

```text
查询 + 身份权限 + 可选的项目上下文
  → 确定可读取的正式结果/版本集合
  → 并行召回：精确名字 / 文本 / 公式结构 / 语义向量
  → 按精确 result revision ID 去重、融合排序
  → 对有权限的候选做 rerank
  → 返回陈述、条件、出处、匹配理由和使用入口
  → 可选：在 Slate 的精确上下文中尝试实例化/检查
```

自然语言发现允许找到尚未安装的结果，但要显示所需包与环境。证明上下文检索则接收精确 goal、local hypotheses、允许的直接 imports、lock digest 和工具链；分别返回“当前环境已有”和“需增加依赖/改变环境”的候选。传递依赖可提供证据，不意味着它的源 namespace 已自动打开。

LeanDojo/ReProver 将证明状态、可访问前提和实际使用注释用于 premise selection，说明这个任务必须考虑证明环境。Pebble 借鉴环境过滤与数据组织，不假设 Lean 的模型或类型系统可直接搬到 Slate。[LeanDojo 论文](https://arxiv.org/abs/2306.15626)。

可先采用 Reciprocal Rank Fusion 融合各通道的排名，避免把全文分数与余弦距离直接相加；候选预算和 rerank 模型通过实际样例选择。pgvector 官方也列出全文与向量结合的 RRF/cross-encoder 路线。[Hybrid search](https://github.com/pgvector/pgvector#hybrid-search)。

明确区别三种反馈：`retrieved` 表示相关候选，`matched` 表示在已声明范围内找到结构匹配/实例化及待证前提，`checked` 才表示精确证明尝试被 Slate 接受。后两者是可选诊断流程，不把搜索分数升级成可导入证明状态。失败或超时不表示定理错误。

任何全文片段、向量候选和 reranker 输入都必须在当前授权范围内；不能先向外部模型发送不可读的候选再过滤。私有项目的 goal/hypotheses 是否发往远端由 Clay/客户端明确选择，本地上下文不会因公开检索自动变成公共索引条目。

## 6. 用现有 Slate 源码检验设计

库中存在下面两个定理，其结论相同，条件不同：

```text
LeftInverseUnique(a, b):  b * a = one -> b = inverse(a)
RightInverseUnique(a, b): a * b = one -> b = inverse(a)
```

来源：[代数例子](https://github.com/sair-math-dev/loom-lang/blob/bab9a76e7864c33e4a90ec6f1b41ba972920d4bf/examples/algebra/inverse_uniqueness.slate)。这里简写参数排序，仅说明检索设计，完整声明仍由原源码导出。

用户搜索“群里的左逆唯一”，文本/语义通道可以召回两个结果；结构记录把第一个前提的乘法参数顺序完整保留。如果 Clay 的上下文有 `b*a=one`、目标为 `b=inverse(a)`，可以优先尝试第一个定理，并报告实例化。第二个定理可能需要额外步骤取得它的前提，不能仅因结论相同就标为立即可用。

研究者点击结果后看到前提、群理论环境、作者/来源、精确版本、引用和添加依赖入口。这是索引直接服务于学术复用的具体闭环。

## 7. 发布与索引的一致性

正式发布事务记录定理目录对象摘要和 outbox event。索引 worker 按 `(result_revision_id, index_revision)` 幂等写入；索引延迟不修改发布的数学状态。精确结果页可直接读目录，搜索尚未更新则明确为索引中。

公开搜索默认只选允许发现的正式版本；每个精确版本记录保留，按明确版本策略分组，锁定上下文查询不能被“最新版本”覆盖。撤回、验证撤销和访问权变化在读取时查当前状态，不能等待异步向量清理才阻止发现/下载。旧事件不得把已撤销结果重新设为公开可用。

更换 embedding/分词版本建立新索引代际，完成覆盖和质量检查后切换查询；不重发包、不生成新证明。尚未审核的自然语言说明与精确声明分字段，编辑说明不会暗中修改已验证目标。

## 8. 实施与评测

第一步完成 Slate 全包声明导出和目录覆盖检查，接名称、文本、精确理论/符号查询及结果页。第二步增加公式结构召回和最小语义向量实验，比较文本、结构、向量及混合方案。第三步由 Clay/Slate 接入 goal 与候选试用；“自动找齐完成整个证明的所有前提”另行评估。

评测集包含：名字查询、中英文概念描述、变量改名、前提变化、同符号不同理论、不同包版本、目标与证明上下文。标注既包括实际使用的前提，也允许专家确认的替代可用定理，避免把唯一历史证明当成唯一正确检索答案。

困难负例优先选择“几乎相同但缺少关键条件”的定理。训练/评测按项目与定理家族隔离，再生成释义，防止同一定理换个名字或语言同时落入训练和测试。关注 Recall@k、排序质量、条件误判、真实导入/使用成功率和端到端延迟；受保护数据检索是独立的权限验收。

当前没有索引数据集、检索 benchmark 或已运行的自动匹配器；不能声称向量检索、结构匹配或某个数据库组合已经达到所需质量。
